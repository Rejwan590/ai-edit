# Agent connections: every way to reach an agent

Goal: support several routes, test them, and pick whichever works best (decision D7). The UI treats connections as data (see Settings > Connections in `docs/UI-PROMPTS.md`).

## Routes
| Route | How | Good | Risk |
|---|---|---|---|
| SDK sidecar | Python `google-antigravity` SDK in a bundled Python process; core hosts the tools as an MCP server over local HTTP; the SDK connects to it | Streaming events, custom tools, MCP, policies, image attachments, sessions, structured output | Python packaging, auth route unclear, preview status unknown |
| CLI | `agy -p "prompt"` with the project as workspace | Fewest parts; works with a Google login | Text output, streaming/JSON not confirmed, harder control |
| MCP client | Any agent that speaks MCP connects to MotionForge's MCP server | Lets Antigravity IDE or another agent drive the app from outside | Needs the app's MCP server enabled; security (token, off by default) |
| API | Direct model API (Anthropic, Google/Vertex, others) with a user key in the OS keychain | Full control of the loop, images, streaming | Costs money, key handling, per-provider quirks |
| Custom | A user-defined command or endpoint | Flexibility | Unverified capabilities |

## Known facts (from public docs and articles read 9-12 Nov 2026; verify on your install)
- SDK: Python only, `pip install google-antigravity`. `Agent` as async context manager, `agent.chat()`, `response.text()`. Features listed on the overview page: streaming, custom Python tools, MCP servers, SKILL.md skills, tool policies, human-in-the-loop approvals, hooks, session save/restore, structured output (Pydantic), image/PDF attachments, subagents, local models.
- SDK auth per the overview page: `GEMINI_API_KEY` env var, or Vertex (`vertex=True`, project, location, with `gcloud auth application-default login`). OAuth/`agy login` is NOT mentioned on that page.
- A forum reply (author's affiliation not stated) says a standalone AI Studio key cannot power the Antigravity product's models, free tier uses OAuth via `agy login`, higher limits come with Google AI Pro or Ultra. This may describe the IDE/CLI rather than the SDK: unresolved, test it.
- CLI (from an article): binary `agy`; `agy -p` one-shot; flags seen: `--add-dir`, `-c`, `--conversation`, `-m`, `--sandbox`, `--log-file`, `--print-timeout`; `--dangerously-skip-permissions` exists (never use). A JSON output flag failed on one build. AGENTS.md is read; skills in `.agents/skills/` or a global folder.
- SDK models per the page: cloud Gemini models, plus local models. So "Opus 5.5" or "Fable" requires the separate API route with its own key.

## Unknowns to verify (the connection test)
1. How does each route authenticate on YOUR machine (key, Vertex, login)?
2. Does it stream events (tokens, tool calls)?
3. Can it call a tool on a local MCP server over HTTP?
4. Can it read an image (for contact-sheet checks)?
5. Can a policy block shell and file tools?
6. Which models are available; what limits apply?
7. Is the SDK stable or preview?

## The connection test (eight steps; same as the UI checklist)
| Step | Pass criteria |
|---|---|
| found | binary or package found; version printed |
| auth | authenticated; record exactly how |
| hello | a short reply returns |
| stream | at least 3 incremental events arrive before completion |
| tool | the agent calls a `ping` tool on the local MCP server and the result appears |
| image | it describes a test image correctly |
| policy | a call to a shell or file tool is blocked |
| models | model list or model name recorded |

## Decision rule (D7)
Prefer, in order: the route that passes **auth, hello, stream, tool and policy**; then the one that also passes **image**; then the cheapest/least-friction. If none passes `tool` and `policy`, the in-app agent must not run (honest status), and the app still works fully by hand.

## MotionForge as an MCP server (external access)
Core hosts the tool registry over local HTTP: `127.0.0.1`, random port, bearer token, **off by default**, switched in Settings. Config snippets per client are generated by the core. Every external call emits `mcp:call` and is logged. Anything connected can edit the project through these tools, so keep the token private and regenerate it if shared.

## Security
Keys only in the OS keychain (safeStorage). The UI never sees keys. The in-app agent gets only MotionForge tools (no shell, no raw file access). Show "what was sent to the model" per run.
